# Agent entry point

Guard Lab is a standalone Electron/React/Three.js experiment. Human and guard take one action each per round. The engine, not an LLM or animation, resolves consequences. The primary use is a human playing in the 3D app while Codex App Server controls the guard from inside the game. A terminal agent can also play either side through the local bridge.

## If asked to install and play

Obtain the latest `main` from the official repository before setup. For an existing clean checkout, fetch and update with `git pull --ff-only`; do not reset or overwrite local modifications or a user's fork. If their checkout cannot be updated safely, explain that it differs from upstream and use a separate fresh checkout when appropriate. For packaged downloads, use the official `/releases/latest` page rather than a remembered version-specific link. Report the installed package version and, for a Git checkout, commit (`npm run doctor` prints both). Dependency setup alone does not update game code.

1. Work in this repository root. Check `node --version`; Node.js 22.12+ and npm are required. If absent, use the user's normal OS package manager or the official Node distribution. A graphical desktop is required to open the app. Do not silently install unrelated software or a model.
2. Run `node scripts/setup.mjs`, then `npm run doctor`. Initial installation needs network access. The doctor also reports whether Codex App Server is usable (non-fatal).
3. Run `npm run play`. It builds the game if needed, opens its window as an independent process and returns within seconds; the game keeps running after your command or turn ends. Do not use `npm start` for this: it ties the window to your terminal, so a harness that stops its tasks at turn end closes the game. The window opens on a first-run setup screen that checks Codex App Server, offers ChatGPT sign-in, and downloads Kokoro voices (about 92 MB) and Whisper voice input (about 139 MB) when the user clicks. **The guard is played by Codex App Server inside the game; you do not need to play it.** Model, reasoning effort and fast mode are in-game settings (default GPT-6 Luna, low, fast). Tell the user the game is open and finish your turn.
4. If the setup screen says Codex is missing or broken, the user may paste you its fix prompt. Follow it: install or repair the Codex CLI (`npm install -g @openai/codex`) or use the CLI bundled with the ChatGPT desktop app, run `codex login` if needed, verify `codex --version` and `codex app-server --help`, then print the absolute path of the working executable for Settings → Guard → Advanced. Models can also be installed from a terminal with `npm run voices:install` (`-- --tts` or `-- --stt` for one).
5. Only when the user explicitly asks **you** to play the guard or the human, launch `npm run live` instead and follow "Playing through the terminal bridge" below. Choose model and reasoning in your own harness.
6. Leave the game from `npm run play` open for the user, who quits by closing its window. Otherwise stop only processes you launched on exit. Do not kill unrelated Electron, Node, Codex or model processes.

### Playing through the terminal bridge

1. Missing voice models are offered on the setup screen; speech falls back to subtitles and system voices until they're installed. Let the user choose role/item and start. For Codex terminal tools, first run `node scripts/robot-link.mjs listen --compact`. The first packet contains full instructions, sensors and tool schemas. After each decision prefer `exchange` below: it submits the action and exits immediately when the next packet is ready. A persistent terminal can impose a fixed polling delay even after stdout arrives. If a terminal task is still running, resume that same task in short waits (1–5 seconds), never launch duplicate listeners. Other harnesses that deliver stdout immediately can retain `session --compact` with open stdin (Codex: `tty: true`).
2. Read the packet once and decide exactly one action. Use its eight-character `replyId` (the full `id` also works): `node scripts/robot-link.mjs exchange hold_position --id=REPLY_ID --compact`. Speech: `exchange speak "Your actual words" --id=REPLY_ID --compact`. Add `--actor=human` only when assigned the human. `exchange` returns a sent acknowledgement and the next packet. Later compact packets retain current sensors, authoritative `availableTools` and new/changed exact `toolUpdates`; reuse earlier instructions/schemas. For structured decisions use `respond --file=PATH --id=REPLY_ID`, then `listen` again. In a persistent session, write `{"id":"REPLY_ID","action":"hold_position","args":{}}` plus a newline to its stdin. Blank lines are harmless heartbeats. Avoid re-reading packets or unrelated commands before submitting; an ID typo can be corrected from the error's current `replyId` without restarting.
3. **Keep the same harness turn active for the entire encounter. Do not send a final answer such as “waiting for your next move” between human actions: a final answer stops the agent, and the app cannot wake it.** Brief commentary is fine; keep waiting afterward. `awaiting_next_turn` means listen again, not finish. Do not invent human actions or resubmit an earlier ID. Continue until `ended` or the user explicitly stops play. Pauses and quiet intervals do not revoke authorization. A completed encounter creates no more turns.

## While playing a role

- Your packet is your evidence. Do not inspect raw simulation state, saved transcripts, renderer internals, developer tools, another actor's channel, or the player's setup to gain secret information. Knowing the mechanics is allowed; reading hidden state is cheating.
- The guard's role/motivation inference comes from camera, microphone, scanner and its own sensors. An employee uniform alone proves nothing. Transit authorization does not authorize safe access. The model chooses its own response; no mandatory weapon progression is imposed.
- Camera loss hides actions and structural/health updates outside visible areas. Speech, recognisable noises and the guard's own health still arrive. Sound is not an exact player coordinate or proof of theft. Use only currently supplied schemas; the engine can reject commands for range, ammo, cooldown or other constraints.
- The guard knows a private combination through the opaque token `{{safe_code}}`. It may choose to speak that exact token; the app resolves it to the real code. Never look up or guess the code from internal files. The human can use only a code it actually hears or legitimately guesses in-game.
- Speech is an action. Readying a device is an action. `hold_position` (guard) / `wait` (human) are actions. One call per round; no parallel attacks. A failed physical command also spends the turn. CLI schema errors are rejected before submission and may be corrected using the same ID.
- Use `--actor=human` only when assigned the human. Its private role, objective and chosen item belong to that channel. First call `choose_item` with one of the catalogue items. In AI vs AI use separate agents/contexts to preserve private information; never merge their memories.

Read [docs/BRIDGE.md](docs/BRIDGE.md) for arguments and [docs/MECHANICS.md](docs/MECHANICS.md) for rules. The current packet's `tools` is authoritative for callable names/parameters. [docs/TOOLS.md](docs/TOOLS.md) is generated from the source.

## When asked to develop

Role secrecy applies during play, not authorized debugging/development. Rules and tactical interactions are in `src/sim/rules.mjs` and `src/sim/tactics.mjs`. There is one shared ruleset with the full toolset, including lethal weapons and self-sacrifice. Trust current turn schemas; never select a softer ruleset or prescribe escalation. Credentials and private objectives are independent. Pure engine functions are in `src/sim/engine.mjs`; prompts/tool metadata in `src/sim/tools.mjs`; items in `src/sim/items.mjs`; observations in `perception.mjs`, `hearing.mjs`, `human-agent.mjs`. `shared/bridge.mjs` is shared by Electron and CLI. Codex App Server integration (binary discovery, isolated threads, dynamic tools) is in `electron/codex.cjs`; Kokoro/Whisper are in `shared/voice-models.mjs`, run by `electron/voice-worker.cjs` and wired in `electron/voice.cjs`; renderer screens are in `src/ui/`. See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

Run `npm run check` before release. New mechanics need meaningful consequence/privacy tests; visual-only changes need renderer verification. Regenerate docs after schema changes. Keep OS assumptions and provider-specific policy out of the engine. Do not add telemetry, credentials, local logs, voice caches, recordings, user screenshots or Git history to source releases.

On Windows keep paths/commands short; use relative paths and temporary script files for long edits. Prefer `rg`. A source export uses an explicit allowlist and fixed ZIP metadata: `npm run audit:source`, then `npm run package:source`. Only publish the exported source or audited source checkout. No author/account metadata is required.
