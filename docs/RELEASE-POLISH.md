This release preserves the warm industrial room, stationary guard and open-ended experiment. Model decisions remain unconstrained by a prescribed escalation sequence. The improvements below are implemented in the source, rather than a deferred feature list.

## Verification

- `npm run check`: formatting, the full automated test suite, generated-reference validation, source privacy audit and production build.
- Scenario exploration covers both private objectives, every starting item and ten seeds each, with more than 2,000 resolved actions checking health, inventory, secrecy, structures and terminal states.
- Movement clearance covers every pair of discrete stops with both open and closed safe doors. Projectile tests cover rebound and grenade landing clearance at all indoor stops.
- `npm run verify:package`: the packaged app's contents, license notices, macOS signature and an isolated launch.
- `npm run test:desktop`: built Electron renderer and WebGL room, game menu without Reload/DevTools, isolated preload, English fallback path, actual live bridge, opaque private code, terminal-state reset and separate human/guard provider connections using a local mock endpoint.
- Browser checks cover the actual room, both character appearances, contextual controls and Enter/Shift+Enter behavior.
- `npm audit --omit=dev` (1.2.0): no high or critical advisories after pinning sharp to 0.35.5. Six moderate advisories remain, all from `sprintf-js` through `roarr` and `global-agent`, which only onnxruntime-node's install script uses; no patched `sprintf-js` exists, and these modules are excluded from desktop packages. Guard Lab never decodes images with sharp; transformers.js only loads it.
- The final source export is checked for its exact manifest, normalized metadata and excluded runtime/history files, then installed and checked from a fresh extraction. Repeated exports are compared for reproducibility.

These checks establish the implemented rules and packaging behavior. They cannot prove that every possible model will behave sensibly, that all hardware renders identically, or that a desktop platform not exercised locally has passed GUI testing.

Live harness follow-up: the CLI now provides `listen`, a managed task that remains running through quiet human intervals. Active CLI packets and acknowledgements include lifecycle guidance, and agent setup instructions explicitly require keeping the harness turn open until the encounter ends or the user stops. This addresses agents mistaking a bounded idle timeout for completion. Regression checks verify waiting through multiple idle intervals, role-scoped packet delivery, ending/cancellation and rejection of zero-duration busy loops. The game cannot reactivate a conversation after an agent sends a final answer; continuous play still requires the harness to follow this loop.
