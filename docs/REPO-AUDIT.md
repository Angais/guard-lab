# Public repository audit

This audit describes the public 1.0.x release and the checks run for it; its test counts and platform results are from that time. Later changes, including the current Node.js 22.12+ requirement, are in the [changelog](../CHANGELOG.md), and [RELEASE.md](RELEASE.md) describes today's package checks.

This review began with a fresh clone of the public repository and fresh downloads of its source ZIP, Windows executable and checksums. It inspected the published content, not only the development folder.

## Packaging correction

The review exercised the public desktop packaging workflow. macOS and Linux created their packages but failed because electron-builder implicitly attempted publication without a token. The build command now specifies `--publish never`; build jobs upload their artifacts separately. Windows and macOS additionally exercise the renderer and actor bridges through the desktop smoke test.

That macOS smoke run exposed a test path check that compared a canonical temporary directory with its symlink alias. The check now canonicalizes both paths; it still verifies containment and removes only its own temporary directory.

## Privacy interpretation

Local machine/account data is excluded from the published source and application payload. Generic loopback URLs, upstream dependency attribution, and RFC private-network examples inside the bundled Electron/Node runtime do not identify the originating machine. Build/release timestamps are ordinary publication metadata, not an embedded personal home path or account token.

GitHub account ownership, public profile information, release authorship and public activity remain visible on GitHub. Anyone needing anonymous hosting should use a suitably separate GitHub identity. Running the app later creates private local preferences, dialogue archives, bridge files and speech caches; those are not included in the repository. See [Privacy](PRIVACY.md).

The corrected release passed 109 tests and source checks on all three CI platforms. Native packaging passed on Windows x64, macOS ARM64 and Linux x64. Windows and macOS additionally passed the actual Electron renderer/bridge/direct-model smoke test. A fresh public clone was installed, diagnosed and smoke-tested on Windows; repeated setup reused the completed install. Downloaded application payloads were inspected for personal markers, identity fields and private runtime/history files. Linux graphical play was not exercised by this CI run; macOS Intel remains available through source setup rather than this ARM64 download.

Passing packaging or smoke checks does not establish subjective graphics quality, performance on every GPU, every model’s behavior, or a complete human playthrough on every platform. Kokoro/Whisper installation, synthesis, transcription and push-to-talk were exercised end to end on macOS (Apple Silicon), including a packaged build; Windows and Linux use the same code with their own onnxruntime binaries but have not had a separate end-to-end speech test.
